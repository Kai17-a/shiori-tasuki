# task-tool 基本仕様

最終更新: 2026-11-06

## 1. 目的

task-tool は、ユーザーのタスクを 1 か所で管理し、その中から AI エージェントに作業を渡すためのツールである。

## 2. 背景

- ユーザーは複数のプロジェクトを兼任していて、タスクがたまっている。
- 日々の作業に AI エージェント（Claude Code・Codex など）を使っている。
- タスクは GitHub Projects・Jira・Notion などに分かれて管理されており、AI エージェントと組み合わせると管理しきれなくなってきた。
- そこで、タスクをこのツールに集め、ここから AI に作業を渡す。

## 3. 基本の考え方

| # | 考え方 | 意味 |
|---|---|---|
| P1 | タスクを 1 か所に集める | どのプロジェクトのタスクも、どこで管理されていたタスクも、このツールで一覧できる。 |
| P2 | AI は頼まれたときだけ動く | ユーザーが「このツールの #N をやって」と頼んだときに、AI が自分で作業を進める。頼まれていないタスクを AI が勝手に始めることはない（自動実行はしない）。 |
| P3 | AI の作業は必ずユーザーが確認する | ユーザーは AI が作ったものを毎回確認する。AI が「終わった」と報告しても、ユーザーが確認するまでタスクは完了にならない。 |
| P4 | AI が何をしたかを必ず追える | AI がタスクに対して何をしたか（分け方、進め方、変更したもの、報告）が、あとから必ず確認できる。 |
| P5 | AI の進め方を見えるようにする | AI が親タスクをどう子タスクに分け（棚卸しし）、どの順にどう実行したかを、画面で見て管理できる。 |

## 4. 使う人と使い方

### 4.1 ユーザー（人）

1. タスクをダッシュボードか CLI で登録・整理する。GitHub の自分の Issue は自動で取り込まれる。
2. AI エージェントとの会話で「task-tool の #N をやって」と頼む。
3. ダッシュボードで、AI の作業の進み具合と記録を見る。
4. AI が完了を報告したタスク（確認中）を確認し、承認するか差し戻す。

### 4.2 AI エージェント

1. 頼まれたタスクを MCP（`get_task`）か CLI（`task-tool view N`）で読む。過去の記録や差し戻しの理由も読む。
2. 着手を記録する（`start_task` / `task-tool start N`）。
3. 大きいタスクは子タスクに分ける（`create_subtasks` / `task-tool split`）。子タスクも順に自分で進める。
4. 進み具合をメモで残す（`add_note` / `task-tool note`）。
5. 終わったら、何をしてどう確かめたかを報告する（`complete_task` / `task-tool done`）。報告されたタスクは「確認中」になる。
6. できなかったときは理由を残して手を離す（`fail_task` / `task-tool fail`）。

作業手順は `task-tool guide` と MCP の説明文で AI に伝える。

## 5. タスクの状態

| 状態 | 意味 | 誰が変えるか |
|---|---|---|
| 未着手（todo） | まだ誰も手を付けていない。差し戻されたタスクもここに戻る。 | 作成時・差し戻し・AI の中止 |
| 進行中（in_progress） | 人か AI が作業している。 | 着手したとき |
| 確認中（review） | AI が完了を報告し、ユーザーの確認を待っている。 | AI の完了報告 |
| 完了（done） | ユーザーが確認して承認した。または、ユーザー自身が終えた。 | ユーザー |

- AI の完了報告は「確認中」にする。「完了」にできるのはユーザーだけ（P3）。
- ユーザーは確認中のタスクを「承認」（→ 完了）か「差し戻し」（→ 未着手、理由を記録）にする。差し戻しの理由は、次に作業する AI が読める。
- 親タスクは、子タスクがすべて「完了」になったときに自動で完了になる。確認中の子が残っている間は完了にしない。
- 進行中のアニメーションは、AI がそのタスクを今まさに作業しているときだけ表示する。人の作業中は表示しない。

## 6. AI の作業記録（P4）

AI がタスクに取り組むたびに、次を記録して画面で見られるようにする。

| 記録 | 取り方 |
|---|---|
| 誰が、いつ着手・報告・中止したか | 着手・完了報告・中止の操作で自動 |
| どの会話（T3 Code のスレッド）で作業したか | 環境変数 `T3CODE_THREAD_ID` があれば自動 |
| どのブランチで、どのコミットからどのコミットまで作業したか | 作業フォルダが git リポジトリなら、着手時と報告時に自動 |
| 変更したファイルと量、コミットしていない変更 | 報告時に自動（git の差分の集計） |
| PR や成果物の URL | AI が報告時に添える |
| 何をしてどう確かめたか | AI の完了報告の文 |
| 進み具合のメモ | AI のメモ |
| ユーザーの承認・差し戻しと、その理由 | ユーザーの操作で自動 |

## 7. 画面（ダッシュボード）

- **概要**: AI が作業中のタスクと担当名、確認待ちのタスク、未着手、今日の完了、停滞を一目で見る。エージェントごとの状態・今日の完了・最後の動きも確認できる。
- **ボード**: 未着手・進行中・確認中・完了の列。ドラッグで状態を変えられる。子タスクは「並べる」か「重ねる」で表示する。
- **タスクのモーダル**: タスクをクリックすると開く。上から次の順に見られる。
  - 状態と親タスク（見出しの下の 1 行）
  - 確認中のときは、AI の報告（要約・変更の記録）と承認・差し戻しを 1 枚の面にまとめて最初に置く
  - 親子関係のツリーと各タスクの状態（P5）
  - AI の作業記録（第 6 節）と、親子全体の作業の経過（どう分けて、どの順に進めたか）
  - 編集、メモ、子タスクの追加、非表示（削除はできない。子タスクごと非表示にし、ボードの「非表示も表示」から戻す）
  - タスクの履歴（親子があるときは、作業の経過と重なるので折りたたむ）
- **アクティビティ**: 全タスクの出来事の新しい順の一覧。概要の「すべて見る」から開き、ヘッダーから概要へ戻る。
- **設定**: 表示（ライト・ダーク、カードの濃さ、背景画像）、GitHub の同期状態・最終同期・エラー・取り込まないリポジトリ、CLI・スキルを使う AI への依頼方法と MCP 接続。

主なナビゲーションはヘッダーパネル左の概要・ボードのタブ。タブには AI が作業中の件数・未完了の件数を表示する。設定は右の歯車から開く。同期状態もヘッダーに表示し、押すとすぐに同期する（設定の「今すぐ同期」も同じ）。同期中は画面の一番上に進捗バーを出す。詳しい結果やエラーは設定で確認する。背景だけを見るリンクは設定とヘッダー（スマートフォンでは非表示）に置く。サイドバーは設けず、画面幅をコンテンツに使う。ボードの表示でリポジトリを選び、完了を「すべて」にすると過去の完了 Issue も表示できる。旧 `#/github` はボード、旧 `#/agents` は設定の AI 案内へ移動する。

## 8. AI との接続

- **MCP**: `task-tool mcp`。Claude Code にはユーザー単位で登録する（T3 Code の中の Claude からも使える）。
- **CLI**: `task-tool`（`gh` 風）。どのフォルダから実行しても同じ DB（`~/.local/share/task-tool/tasks.db`）を使う。`--json` で機械向けの出力を返す。
- **誰が操作したか**: MCP は接続した AI の名前、CLI は `--as` か `TASK_TOOL_ACTOR`。Claude Code から実行した CLI は自動で `claude-code` になる。

## 9. タスクの取り込み元

| 取り込み元 | 状態 |
|---|---|
| 手で登録（ダッシュボード・CLI・AI） | 対応済み |
| GitHub Issues（自分のリポジトリで自分が作ったものと、自分が担当のもの） | 対応済み（5 分ごとに自動同期） |
| GitHub Projects | 未対応 |
| Jira | 未対応 |
| Notion | 未対応 |

自分のアカウントのリポジトリ（アーカイブを除く）で自分が作ったIssueと、リポジトリを問わず自分が担当のIssueを取り込み（他の人が立てて自分が担当でないIssueは、外部の入力がAIに届くのを防ぐため取り込まない。設定で取り込まないことにしたリポジトリは除く。追加時に取り込み済みのタスクを削除する）、GitHubの親も取り込み済みの場合は親子関係を毎回同期する。未取り込みの親は作成しない。ローカルの親・子タスクの関係は保持し、親子関係の同期では状態を変更しない。

GitHub にリンクされたタスク（ローカルで作成後に GitHub に公開したものも含む）の題名と説明は GitHub で管理し、task-tool からの実変更はストア層で拒否する。同値の再送は許可する。画面では読み取り専用にし、編集先の Issue リンクを表示する。API は HTTP 409、CLI は非ゼロ終了、MCP はツールエラーを返す。同期による題名・説明の更新は継続する。状態・担当・作業フォルダ・メモ・子タスク・承認・差し戻し・非表示は引き続き操作できる。

## 10. 実装の状況と今後

### 対応済み

- タスクの登録・編集・親子関係・メモ（画面・CLI・MCP）と非表示（画面・CLI。削除の機能は持たない）
- GitHub Issues の自動取り込み
- MCP と `gh` 風 CLI による AI からの操作
- 親子関係のモーダル、ボードの「並べる・重ねる」表示、AI が作業中のときだけのアニメーション

- 確認の流れ（第 5 節）: AI の完了報告を「確認中」にし、ユーザーの承認・差し戻しを画面と CLI に加える。
- AI の作業記録（第 6 節）: 着手から報告までの git の記録、T3 Code のスレッド、成果物の URL を自動で残し、モーダルに表示する。
- 作業の経過の可視化（P5）: 親子全体で、どう分けてどの順に進めたかをモーダルで時系列に見られるようにする。

### 今後の候補

- プロジェクトの単位: 複数のプロジェクトをまたいでタスクを分けて見る。
- 取り込み元の追加: GitHub Projects・Jira・Notion。
- T3 Code との連携の強化: ダッシュボードから T3 Code のスレッドで作業を始める（`t3 thread start`）、スレッドの中にタスクの画面を出す（MCP Apps）。

## 11. やらないこと

- 頼まれていないタスクを AI に自動で実行させること（P2）。
- AI の完了報告だけでタスクを完了にすること（P3）。
